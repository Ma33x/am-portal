# Ревью безопасности и качества — 27 октября 2026

## Объём

Проверены исходники Python и JavaScript, выдача и отзыв ключей, авторизация API, установщик, конфигурация nginx/systemd и соответствие README реализации. Проведены локальные автоматические проверки. Рабочие VPS в рамках этого ревью не изменялись.

## Исправлено

| Проблема | Изменение |
|---|---|

| QR-API принимал произвольный текст от владельца любой действующей ссылки | Генерация только для активного ключа этой ссылки; переполнение QR возвращает 422 |
| Нестандартный токен или неверный тип ID могли приводить к 503 | Строгая проверка токена, дублированных Authorization и идентификаторов |
| Маршруты master API сопоставлялись по окончанию пути | Сопоставление полного пути |
| Чтение тела запроса не отвергало неоднозначные заголовки длины | Запрет Transfer-Encoding и дублированных Content-Length |
| При обработке AllowedIPs разворачивалась вся подсеть в множество адресов | Проверка принадлежности подсетям без разворачивания; пул выдачи ограничен /16 и меньше |

| На HTTP-входе nginx оставался access-log, вопреки общему описанию README | Отключён также в HTTP-блоке для новых установок |
| Импорт server.py читал конфигурацию и запускал восстановление | Явная инициализация при старте; HTTP-обработчик можно тестировать отдельно |
| Код Python был сжат в длинные строки, были лишние импорты | Форматирование Ruff, удаление неиспользуемых импортов |
| README не объяснял обновление после одноразового bootstrap и границы обновления | Добавлены инструкции получения клона, обновления заглушки и сохранения nginx/systemd |

## Что проверено

- SQL использует параметры; имена пользователей не подставляются в команды shell.
- Динамические строки интерфейса вставляются через textContent, а не innerHTML.
- Повтор запроса и восстановление после сбоя не расходуют дополнительную квоту.
- Отозванный ключ не возвращается через пользовательскую ссылку.
- Мастер-API проверяет токен и, если задан, список IP.
- Ограничение IP мастер-доступа не блокирует пользовательские ссылки.
- HTTPS/API-ответы с секретами имеют no-store; nginx передаёт клиентский IP самостоятельно.
- Приватные конфигурации, базы и рабочие секретные ссылки не входят в отслеживаемые файлы проекта.

## Оставшиеся ограничения

Это ревью исходного кода, а не независимый пентест или гарантия отсутствия уязвимостей. Не выполнялись нагрузочный тест из внешней сети, анализ бинарников AWG, аудит ОС/пакетов и повторная установка на чистой машине после исправлений.

Backend имеет root-доступ к Docker; эксплуатация ошибки backend может скомпрометировать VPS. Ключи в SQLite не шифруются. Все владельцы одной пользовательской ссылки видят ключи этой ссылки. Rate limit не заменяет сетевую защиту от DDoS.

Несколько независимых процессов или ручное редактирование AWG одновременно с порталом не поддерживаются. Изменения конфигурации контейнера и SQLite не являются единой транзакцией: восстановление рассчитано на сохранённые состояния pending/revoking, а не на потерю или повреждение файлов контейнера.

Установщик не откатывает пакеты, сертификат и все частично созданные файлы при ошибке. Он сохраняет состояние для диагностики и отказывается перезаписывать существующую установку. Bootstrap исполняет текущий код main с root-правами; для контроля цепочки поставки используйте просмотренный commit.

Ранее установленные порталы получают исправления backend после обновления и перезапуска. Изменения nginx требуют отдельного переноса в действующую конфигурацию и `nginx -t` перед reload.
