# AM Portal

Свой портал выдачи ключей **AmneziaWG 2** на вашем VPS. Пользователь открывает секретную ссылку, вводит имя, выбирает устройство и получает `vpn://`, QR-код и `.conf`. Владелец создаёт ссылки с ограниченным количеством выдач и отзывает отдельные ключи.

## Что умеет

- Мастер-ссылка и отдельные пользовательские ссылки с лимитами 1–1000.
- Имена с обозначением устройства: `[P]` — ПК, `[M]` — телефон, `[G]` — роутер.
- Повторное копирование и QR для уже полученных ключей.
- Увеличение QR и скачивание исходного PNG.
- Повтор запроса после сбоя не расходует дополнительный ключ.
- Отзыв ключа отключает его в AWG. Использованный лимит не возвращается.
- Отключение ссылки закрывает доступ к выдаче и просмотру; уже установленные VPN-профили работают до отдельного отзыва.
- Свой домен либо бесплатный адрес sslip.io / nip.io, HTTPS с автоматическим продлением.
- Необязательное ограничение мастер-доступа по IP. Пользовательские ссылки этим ограничением не затрагиваются.

## Требования

Ubuntu 24.04 или Debian 12, Python 3.10+, systemd, root-доступ и **уже установленный AmneziaWG 2 в Docker**. Ожидаются интерфейс `awg0` и файлы `/opt/amnezia/awg/awg0.conf`, `/opt/amnezia/awg/clientsTable` внутри контейнера. Обычно контейнер называется `amnezia-awg2`.

Установите AmneziaWG через приложение Amnezia VPN заранее. Портал не устанавливает VPN, не меняет его обфускацию и не перезапускает контейнер. Другие варианты WireGuard/AmneziaWG пока не поддерживаются.

Публичные TCP-порты **80 и 443** должны быть доступны серверу nginx; существующий UDP-порт AmneziaWG тоже должен быть открыт. При NAT пробросьте их. Если 443 занят другим приложением, автоматическая установка не подходит: необходима ручная интеграция в существующий reverse proxy. Firewall установщик не меняет.

## Установка

Выполните на **своём VPN-сервере**:

```bash
sudo apt-get update
sudo apt-get install -y git python3
git clone https://github.com/Ma33x/am-portal.git
cd am-portal
sudo python3 install.py
```

Мастер спросит:

1. Свой домен, sslip.io или nip.io.
2. Публичный IPv4 сервера.
3. Домен, если выбран собственный. Его A-запись должна уже указывать на этот IPv4. Для автоматической установки уберите лишние A/AAAA-записи и отключите CDN-проксирование.
4. Имя работающего AWG-контейнера.
5. Email для сертификата Let's Encrypt.
6. Разрешённые IP администратора через запятую — либо пустую строку, чтобы доступ определялся только мастер-ссылкой.

После проверок подтвердите `yes`. Установщик добавляет отдельный nginx-сайт, Python-службу и сертификат. При успехе выводит мастер-ссылку. Не пересылайте её пользователям: создавайте для них отдельные ссылки в панели.

## Домен и смена IP

**Свой домен рекомендуется для переезда.** Например, `vpn.example.com`: меняете A-запись, сохраняете ключи сервера, настройки AWG, UDP-порт и клиентские пиры. Клиентам может потребоваться переподключение, перезапуск приложения и ожидание DNS-кеша. Домен не заменяет перенос данных VPN.

**sslip.io / nip.io** дают имя без регистрации, например `am-203-0-113-10.sslip.io` (документационный пример). IP встроен в имя. **Такое имя нельзя перенаправить на другой IP:** при переезде адрес и клиентские конфигурации придётся менять. Бесплатный DNS не скрывает IP и не гарантирует доступность при блокировках. Выдача HTTPS-сертификата зависит от доступности сервиса и лимитов центра сертификации.

Описание сервисов: [sslip.io / nip.io](https://sslip.io/). Если нужен бесплатный адрес, сохраняющийся при смене IP, можно самостоятельно настроить динамический DNS и в установщике выбрать «свой домен».

В VPN-ключи записывается выбранный **домен**, а не числовой IP. Оболочка `vpn://` содержит упакованные настройки, поэтому домен не виден непосредственно в строке ссылки.

## Страница-заглушка

На главном адресе открывается отдельная страница Secure Connection в тёмном оформлении. На ней нет ссылок на мастер-панель или выдачу. Шаблон — `landing.html`, установленная копия — `/var/www/am-portal/index.html`. Его можно заменить своим HTML. Секретные ссылки ведут на `/access/#…`.

## Как пользоваться

Откройте мастер-ссылку → укажите название и лимит → создайте ссылку → отправьте её пользователю. Все обладатели одной ссылки видят все ключи, выданные по ней: для независимых людей создавайте отдельные ссылки.

Пользователь вводит имя, выбирает устройство, создаёт ключ и импортирует его в Amnezia. Для роутера доступен файл `.conf`; требуется поддержка AmneziaWG 2. QR можно увеличить или скачать, а ранее выданные ключи — скопировать повторно.

## Файлы и обслуживание

| Путь | Назначение |
|---|---|
| `/opt/am-portal` | Код и интерфейс |
| `/etc/am-portal/config.json` | Домен, контейнер, мастер-токен, IP администратора |
| `/var/lib/am-portal/portal.sqlite` | Ссылки, лимиты и ключи |
| `/etc/nginx/sites-available/am-portal` | HTTPS-вход |
| `/etc/systemd/system/am-portal.service` | Служба портала |

```bash
sudo systemctl status am-portal --no-pager
sudo journalctl -u am-portal -n 50 --no-pager
sudo nginx -t
sudo certbot renew --dry-run
```

Повторная установка поверх существующей конфигурации намеренно запрещена. При неудачной первичной установке файлы сохраняются для диагностики: исправьте DNS/занятые порты/доступность сертификата, затем завершите настройку вручную. Не удаляйте базу работающего портала.

Мастер-ссылку можно восстановить на сервере:

```bash
sudo python3 - <<'PY'
import json
c=json.load(open('/etc/am-portal/config.json'))
print(c['origin']+'/access/#m/'+c['master_token'])
PY
```

Список `admin_ips` применяется только к мастер-API. После изменения конфигурации перезапустите `am-portal`. Backend слушает исключительно `127.0.0.1:8792`; не публикуйте этот порт напрямую. Заголовок клиентского IP задаёт nginx.

## Резервная копия

База содержит приватные ключи: храните резервные копии закрыто и не коммитьте их в Git.

```bash
sudo bash <<'SH'
set -eu
backup="/root/am-portal-backup-$(date +%Y%m%d-%H%M%S)"
umask 077
mkdir "$backup"
systemctl stop am-portal
trap 'systemctl start am-portal' EXIT
cp -a /etc/am-portal "$backup/config"
cp -a /var/lib/am-portal "$backup/data"
SH
```

Для переезда также нужен бэкап самого AWG-контейнера: серверные ключи, конфигурация, `clientsTable` и остальные настройки Amnezia. Одной базы портала недостаточно. Не выдавайте ключи параллельно через несколько копий портала или сторонние скрипты: синхронизация записей между независимыми процессами не реализована.

## Обновление

Сначала сделайте резервную копию. Затем в каталоге клона:

```bash
git pull --ff-only
sudo bash <<'SH'
set -eu
systemctl stop am-portal
trap 'systemctl start am-portal' EXIT
for f in server.py store.py awg.py index.html app.js style.css; do
  install -m 600 "$f" "/opt/am-portal/$f"
done
SH
```

Конфигурация и база не заменяются. Изменение `endpoint` влияет только на будущие выдачи: сохранённые и импортированные ранее профили требуют отдельного обновления.

## Проверки разработки

```bash
python3 -m unittest discover -v
node --check app.js
```

Тесты проверяют параллельные лимиты, восстановление после прерванной выдачи, отзыв, изоляцию пользовательских ссылок, DNS-валидацию и домен в формате Amnezia. Проверки с имитацией AWG не заменяют проверку реального VPN-подключения на целевой машине.

## Модель доступа

Портал управляет Docker и потому работает с правами root. Мастер-токен — административный секрет. Пользовательская ссылка — секрет доступа к выданным по ней ключам. Данные хранятся локально, без внешнего сервиса аккаунтов. HTTPS обязателен; запросы и ключи не пишутся в access-log. Не публикуйте конфигурацию, базу и скриншоты с действующими ключами.
